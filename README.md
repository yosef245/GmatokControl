# גוונים של מתוק · ניהול הזמנות וייצור

מערכת לניהול הזמנות, לוח ייצור, מלאי חומרי גלם ומשלוחים, לפי האפיון המאושר.
Next.js (App Router) + Supabase (Postgres, Auth באימייל וסיסמה, הרשאות ברמת שורה), בעברית ומימין לשמאל.

## מה יש כאן (ספרינט 0)

- כניסה באימייל וסיסמה. מי שהאימייל שלו ברשימת העובדים נכנס עם התפקידים שלו; **המשתמש הראשון במערכת ריקה הופך למנהל מפעל**. כניסה ב־SMS תתווסף בהמשך (מסד הנתונים כבר תומך בה).
- תפריט לפי תפקיד (מנהל מפעל, משווק, מנהל ייצור, עובד ייצור, מחסן ושילוח).
- דף בית: הזמנות פתוחות, איחורים וסיכונים, חומרים באדום, עומס ייצור, ויוצאות היום ומחר.
- מלאי: במלאי, שמור, זמין, מינימום וכמה להזמין, עם צבעי התראה.
- מסד הנתונים המלא לפי האפיון: טבלאות, הרשאות לכל תפקיד, סימון ייצור עם חלוקה בין הזמנות וביטול תוך 10 דקות, הורדת מלאי לפי מתכון.
- שאר המסכים מסומנים "בפיתוח" עם מספר הספרינט.

## הקמה

1. **Supabase**: פותחים פרויקט חדש ב־[supabase.com](https://supabase.com) (אזור קרוב, למשל Frankfurt).
2. **מסד נתונים**: ב־SQL Editor מריצים לפי הסדר את הקבצים ב־`supabase/migrations` (`20260929000000_init.sql`, `20260929120000_email_login.sql`, `20260930000000_orders.sql`, `20261001000000_production.sql`, `20261002000000_deliveries_prices.sql`, `20261003000000_whatsapp.sql`, `20261004000000_staff_passwords.sql`, `20261005000000_speed_security.sql`). בכל ספרינט שמוסיף קובץ, מריצים רק את החדש
   (או עם ה־CLI: `supabase link` ואז `supabase db push`).
   את `supabase/seed.sql` מריצים **רק בסביבת פיתוח**; הוא יוצר נתוני הדגמה ועובדים פיקטיביים.
3. **משתמשים**: Authentication → Users → Add user → Create new user, עם אימייל וסיסמה ו־Auto Confirm User מסומן.
   את זה עושים רק פעם אחת, למנהל המפעל: המשתמש הראשון שנוצר הופך למנהל. את שאר העובדים מוסיפים מהאפליקציה (הגדרות ← עובדים): לכל עובד שנוסף עם אימייל נוצרת סיסמה זמנית שמוצגת פעם אחת, והוא בוחר סיסמה משלו בכניסה הראשונה. שם גם מאפסים סיסמה (נוצרת סיסמה זמנית חדשה), ומבטלים ״פעיל״ כדי לחסום כניסה.
   **חובה** לכבות הרשמה עצמית אחרי שהמנהל נוצר: Authentication → Sign In / Providers → Allow new users to sign up. אחרת כל אחד יכול לפתוח חשבון במערכת.
4. **משתני סביבה**: מעתיקים את `.env.example` ל־`.env.local` וממלאים את כתובת הפרויקט ומפתח ה־anon (Project Settings → API).
5. **הרצה מקומית**: `npm install` ואז `npm run dev`, ונכנסים ל־http://localhost:3000.
6. **העלאה לאוויר**: מחברים את המאגר ל־[Vercel](https://vercel.com/new), מוסיפים את שני משתני הסביבה, ו־Vercel בונה כל שינוי ב־main.
   ב־Supabase מוסיפים את כתובת האתר תחת Authentication → URL Configuration.

## הכנה לפיילוט

1. בהגדרות ← העסק: שם, טלפון, כתובת, ח.פ., מע״מ, מספר עובדים ושעות משמרת.
2. בהגדרות ← ייבוא מאקסל, לפי הסדר: מוצרים, חומרי גלם (עם עמודת מלאי = ספירת פתיחה), מחירונים, לקוחות. לכל סוג יש תבנית להורדה.
3. בהגדרות ← מוצרים: מתכון לכל מוצר (בלי מתכון המלאי לא יורד בייצור).
4. בהגדרות ← עובדים: מוסיפים את כל העובדים עם אימייל ותפקיד, ומעבירים לכל אחד את הסיסמה הזמנית שלו.
5. שבוע ראשון: כל הזמנה חדשה נכנסת למערכת, הייצור מסומן בלוח, והמחסן מסמן יציאה ומסירה. בסוף השבוע עוברים על הדוחות ועל ספירת מלאי.

## WhatsApp Business

בלי חיבור, כפתורי הוואטסאפ פותחים הודעה מוכנה בוואטסאפ של הטלפון. כדי לשלוח ישירות מהמערכת:
הגדרות ← וואטסאפ מציג את שלבי החיבור ב־Meta, את נוסח ארבע התבניות לאישור, ואת כתובת ה־Webhook והטוקן שלו.
ב־Vercel מוסיפים את המשתנים `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_VERIFY_TOKEN` ו־`WHATSAPP_APP_SECRET` (חובה: בלעדיו עדכוני הסטטוס מ־Meta נדחים), ועושים Redeploy.
